# Ленивая загрузка

Прежде чем разбирать API — нужно понять саму идею.

Представьте статью с тысячей комментариев. Грузить их все сразу — значит заставить
пользователя ждать ради того, что он, скорее всего, никогда не прочитает. Ленивая загрузка
работает по другому принципу: показываем сколько нужно, а остальное догружаем в тот момент,
когда человек до него докрутил.

В WEX это сделано на двух уровнях:

- **ленивые компоненты** — HTML и JS компонента скачиваются только когда он понадобился
- **ленивые списки** — данные подгружаются порциями по мере прокрутки (`w-lazy`)

Под капотом списки используют нативный `IntersectionObserver`: браузер сам сообщает,
когда край списка появился на экране. Никаких обработчиков `scroll`, никаких лишних
вычислений на каждый кадр.

Базовый пример готовой страницы лежит по пути: `demo/Lazy`.

## Ленивые компоненты

Обычный компонент начинает загружаться сразу, как только вы его зарегистрировали:

```js
.component('Article', 'Components/Article.html')
```

Если страница «Статья» открывается не у каждого посетителя, это лишний трафик.
Третьим аргументом можно сказать «не торопись»:

```js
.component('Article', 'Components/Article.html', { lazy: true })
```

Теперь файл скачается в одном из двух случаев:

- тег `<Article>` впервые попал в шаблон, который рендерится прямо сейчас
- его прогрел prefetch у `<Link>` (см. документацию роутера)

Заметьте: тег внутри скрытого блока `w-route` в шаблон не попадает. Пока маршрут не
активен, компонент не грузится — и это именно то, что нужно.

Пока компонент скачивается, на его месте пусто. Как только он готов, вью перерисуется
сама. Если загрузка упала (сеть, 404), Wex попробует ещё два раза с паузой, а при полном
провале покажет ошибку в консоли и позволит повторить попытку при следующем рендере
или наведении на ссылку.

## w-lazy — подгрузка списка при прокрутке

Директива вешается на контейнер списка. Wex следит за краем этого контейнера
и сообщает вам, когда он оказался рядом с экраном. Что именно подгружать и откуда —
решаете вы, в обработчике события `$lazy`.

### Подгрузка вниз

Классический случай: комментарии, лента, каталог.

```html
<div w-lazy="down">
    <div w-for="c in comments" class="py-3 border-b">
        {{ c.text }}
    </div>
</div>
```

```js
$('#comments')
    .state({ comments: [] })
    .on('$lazy', (state, lazy) => {
        $wire.get(`/api/comments?page=${lazy.page}`)
            .done((items) => {
                if (!items.length) return lazy.end()   // данных больше нет

                items.forEach(item => state.comments.push(item))
                lazy.done()                             // можно грузить следующую порцию
            })
            .fail(() => lazy.fail())                    // повторим через 3 секунды
    })
    .mount()
```

Пустой список тоже работает: край контейнера уже виден, значит, первая порция
запросится сразу после монтирования. Отдельно «стартовую» загрузку писать не нужно.

### Подгрузка вверх

Переписка, как во ВКонтакте: новые сообщения внизу, а старые догружаются, когда
крутишь вверх. Контейнер с `overflow-y: auto` Wex находит сам — это ближайший
прокручиваемый предок.

```html
<div class="h-[70vh] overflow-y-auto">
    <div w-lazy="up">
        <div w-for="m in messages">{{ m.text }}</div>
    </div>
</div>
```

```js
.on('$lazy', (state, lazy) => {
    const oldest = state.messages[0]?.id ?? ''

    $wire.get(`/api/messages?before=${oldest}`)
        .done((older) => {
            if (!older.length) return lazy.end()

            state.messages.unshift(...older)   // старые — в начало списка
            lazy.done()
        })
})
```

Здесь есть неочевидная проблема. Когда сверху добавляются элементы, всё содержимое
сдвигается вниз, и пользователя выбрасывает на другое место переписки. Wex запоминает
позицию прокрутки перед подгрузкой и после перерисовки сам возвращает пользователя
туда, где он был. Вам для этого ничего делать не нужно.

Если чат открывается и сразу должен показать последние сообщения, сначала отрисуйте
начальную порцию и прокрутите контейнер вниз. Иначе край сверху окажется на экране
и первая подгрузка уйдёт без вашего ведома.

## Объект lazy

Обработчик `$lazy` получает вторым аргументом объект с данными и тремя методами:

| Поле | Что это |
|------|---------|
| `lazy.page` | номер подгрузки, начиная с 1 |
| `lazy.offset` | сколько элементов в списке сейчас (удобно для курсорной пагинации) |
| `lazy.direction` | `'down'` или `'up'` |
| `lazy.el` | контейнер списка |
| `lazy.done()` | порция добавлена, можно грузить следующую |
| `lazy.end()` | данные закончились, подгрузка больше не нужна |
| `lazy.fail(ms)` | ошибка: подождать (по умолчанию 3000 мс) и попробовать снова |

Главное правило: **`lazy.done()` вызывается после записи в state**, а не до.
Пока вы не вызвали `done()`, `end()` или `fail()`, новые запросы не стартуют —
поэтому один и тот же запрос не уйдёт дважды, сколько бы пользователь ни крутил.

## Настройка директивы

Атрибуты на контейнере:

```html
<div w-lazy="down"
     w-lazy-margin="400px"
     w-lazy-root="#feed"
     w-lazy-key="query">
```

- `w-lazy-margin` — за сколько пикселей до края начинать подгрузку. По умолчанию `200px`:
  данные приходят раньше, чем пользователь долистает до конца, и он не видит паузы.
- `w-lazy-root` — CSS-селектор прокручиваемого контейнера. Нужен, только если автоопределение
  не подходит. Без него Wex берёт ближайший прокручиваемый предок или окно браузера.
- `w-lazy-key` — выражение, при смене которого список начинается заново.

### Сброс списка по ключу

Поиск, фильтр, смена вкладки: пользователь изменил условие, и подгружать нужно
уже другой список с первой страницы. Для этого есть `w-lazy-key`:

```html
<div w-lazy="down" w-lazy-key="query">
    <div w-for="r in results">{{ r.title }}</div>
</div>
```

```js
.state({ query: '', results: [] })
.on('input', '.search', function(state) {
    return (e) => {
        state.query = e.target.value
        state.results = []        // очищаете список вы сами
    }
})
.on('$lazy', (state, lazy) => {
    $wire.get(`/api/search?q=${state.query}&page=${lazy.page}`)
        .done((items) => {
            if (!items.length) return lazy.end()
            state.results.push(...items)
            lazy.done()
        })
})
```

Как только `query` поменялся, счётчик `lazy.page` обнуляется и подгрузка включается снова,
даже если до этого вы вызывали `lazy.end()`. Список при этом Wex не очищает: это ваши данные.

## Настройки по умолчанию

Если хочется поменять поведение для всего сайта, один раз подключите плагин:

```js
const { createLazy } = window.jqvm

$('#app')
  .state()
  .plugin(createLazy({
      margin: '300px',   // отступ до края
      timeout: 15000,    // через сколько мс считать, что done() забыли
  }))
  .mount()
```

Плагин нужен только для настроек. Сама директива `w-lazy` доступна во всех компонентах
сразу, ничего подключать не надо.

## Предохранители

Ленивая загрузка легко превращается в бесконечный цикл запросов, поэтому у Wex есть защита:

- **Забыли вызвать `done()`.** Через `timeout` (15 секунд) подгрузка разблокируется сама.
- **Сервер вернул ошибку.** `lazy.fail()` не даёт долбить сервер: пауза 3 секунды,
  потом ещё одна попытка.
- **Список не растёт.** Если вызвали `done()`, а количество элементов не изменилось,
  после второго такого раза подгрузка остановится, а в консоли появится предупреждение.
  Когда данные кончились, вызывайте `lazy.end()`: так честнее.
- **Контейнер удалён.** Наблюдатель отключается сам, утечек нет.

## Подводные камни

**Контейнер должен содержать сам список.** `w-lazy` смотрит на первый (для `up`) или
последний (для `down`) элемент внутри контейнера. Если рядом лежат посторонние блоки,
выносите список в отдельный `<div>`.

**Элементы с `display: contents`.** Такие элементы не имеют размеров, и браузер не может
сказать, видны ли они. Wex заглядывает внутрь и берёт ближайший настоящий элемент,
так что `w-for` на обёртках работает без дополнительных усилий.

**Прокрутка в Safari.** Для `up` Wex отключает нативную коррекцию прокрутки браузера
(`overflow-anchor`) и возвращает позицию сам, чтобы не было двойного сдвига.
Это одинаково работает и в Chrome, и в Safari.

**Данные приходят пропом.** Если список лежит в родительском компоненте и передаётся
дочернему через `:comments="comments"`, подгрузку лучше вешать там, где живёт state.
Тогда `$lazy` пишет данные напрямую в свой же стейт.

## Коротко
- `.component(name, url, { lazy: true })` — компонент грузится по требованию
- `w-lazy="down"` и `w-lazy="up"` — подгрузка при прокрутке вниз и вверх
- `.on('$lazy', (state, lazy) => ...)` — вы решаете, откуда брать данные
- `lazy.done()` после записи в state, `lazy.end()` когда данные кончились, `lazy.fail()` при ошибке
- `w-lazy-key` — начать список заново при смене условия
