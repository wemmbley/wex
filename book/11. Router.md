# Встроенный роутер

Прежде чем разбирать API — нужно понять саму идею.

Когда пользователь переходит по ссылке на обычном сайте, браузер загружает новую
страницу целиком. Роутер в WEX перехватывает эту навигацию и говорит браузеру:
«не перезагружай страницу, я сам разберусь что показать». Адресная строка меняется,
кнопка «назад» работает — но страница не перезагружается. Это и есть клиентский роутинг.

Под капотом роутер переписывает нативные `history.pushState` и `history.replaceState`,
слушает `popstate` — и при любом изменении URL уведомляет вью чтобы та перерисовалась
с учётом нового адреса.

А ещё роутер знает, куда пользователь пойдёт дальше. Пока курсор только летит к ссылке,
он уже качает компонент и данные будущей страницы. К моменту клика всё лежит в кэше,
и страница открывается мгновенно. Об этом — в разделе про `<Link>`.

## Подключение
Роутер подключается как плагин через `.plugin()`:
```js
const { createRouter } = window.jqvm

const router = createRouter({
    mode: 'hash', // или 'history'

    // необязательный параметр: именованные маршруты
    // нужны для удобства, генерации ссылок и prefetch
    // формат: имя маршрута и значение
    routes: {
        'home': '/',
        'post.show': {
            path: '/post/{id:\\d+}',
            component: 'Components/Article.html',
            // позже тут будет ваш API
            data: ({ id }) => [`Structures/Post-${id}.json`],
        },
    },
})

$('#app')
  .state()
  .plugin(router)
  .mount()
```

Значение маршрута может быть просто строкой (`'home': '/'`) — тогда это только путь.
Объект нужен, когда вы хотите prefetch: `component` — адрес компонента страницы,
`data` — адреса данных (массив или функция, которая получает параметры пути).

## Два режима работы:
### hash-режим
URL выглядит как site.ru/#/catalog.
Работает везде без настройки сервера.
Хэш-часть никогда не отправляется на сервер, роутер читает её сам.

### history-режим
URL выглядит как site.ru/catalog.
Красиво, но требует настройки сервера чтобы все пути возвращали
один и тот же index.html. На Apache или Nginx это пара строк в конфиге.

## w-route — показать блок для конкретного маршрута
Это директива-аналог `w-if`, но условие — текущий URL а не стейт.
Значение — это шаблон пути, как в Laravel:

```html
<template id="app">
    <nav>
        <a href="#/" w-navigate="push">Главная</a>
        <a href="#/catalog" w-navigate="push">Каталог</a>
        <a href="#/about" w-navigate="push">О нас</a>
    </nav>

    <div w-route="/">
        <h1>Добро пожаловать!</h1>
        <p>Это главная страница.</p>
    </div>

    <div w-route="/catalog">
        <h1>Каталог товаров</h1>
    </div>

    <div w-route="/about">
        <h1>О нас</h1>
    </div>
</template>

<script>
    $('#app').state().mount()
</script>
```

Заметьте: кавычки внутри кавычек больше не нужны. Значение `w-route` — это не выражение,
а строка-шаблон. Старая запись `w-route="'/catalog'"` по-прежнему работает, но писать её незачем.

Блок, чей маршрут не совпал, на странице не появляется вообще.
Всё, что внутри него (`w-if`, компоненты, `$route.params`), даже не вычисляется.

### Синтаксис шаблона

| Запись | Что значит | Пример совпадения |
|--------|------------|-------------------|
| `/post/{id}` | обязательный параметр | `/post/42` |
| `/post/{id?}` | необязательный параметр | `/post` и `/post/42` |
| `/post/{id:\d+}` | параметр с ограничением (регулярка) | `/post/42`, но не `/post/abc` |
| `/files/{path*}` | всё остальное, включая слеши | `/files/a/b/c.txt` |
| `post.show` | имя маршрута из таблицы `routes` | то, что описано в таблице |
| `regex:/^\/a/i` | сырая регулярка | всё, что она пропустит |

Прямо в HTML ограничение пишется с одним слешем: `w-route="/post/{id:\d+}"`.
В JS-строке (в таблице `routes`) слеш нужно удвоить: `'/post/{id:\\d+}'`.

Есть одно ограничение: внутри `{name:regex}` нельзя использовать фигурные скобки,
то есть `\d{2}` не сработает. Пишите `\d\d` или берите `regex:`.

Если подходят сразу несколько маршрутов, побеждает первый из таблицы `routes`,
затем — те, что встретились только в шаблонах.

## w-navigate — умные ссылки
Обычный `<a href>` вызовет полную перезагрузку страницы. `w-navigate` перехватывает клик
и передаёт навигацию роутеру:

```html
<!-- push — добавляет в историю (можно вернуться назад) -->
<a href="#/catalog" w-navigate="push">Каталог</a>

<!-- replace — заменяет текущую запись в истории -->
<a href="#/login" w-navigate="replace">Войти</a>

<!-- back / forward — как кнопки браузера -->
<button w-navigate="back">← Назад</button>
<button w-navigate="forward">Вперёд →</button>

<!-- open — новая вкладка -->
<a href="https://google.com" w-navigate="open">Открыть</a>
```

## Link — ссылка, которая готовит страницу заранее
`w-navigate` просто переходит. `<Link>` умеет больше: он строит адрес по имени маршрута
и начинает загрузку страницы ещё до клика. Под капотом это обычный `<a>`,
поэтому любые ваши классы и атрибуты работают как обычно:

```html
<!-- по имени маршрута и параметрам -->
<Link to="post.show" :params="{ id: 3 }" class="btn btn-primary">
    Читать далее
</Link>

<!-- по готовому пути -->
<Link to="/about" class="link">О нас</Link>

<!-- имя маршрута из выражения -->
<Link :to="item.route" :params="{ id: item.id }">{{ item.title }}</Link>
```

Лишние ключи в `:params` (которых нет в шаблоне пути) уходят в query:
`:params="{ id: 3, page: 2 }"` даст `#/post/3?page=2`.

### Как работает prefetch
Ссылка начинает грузить страницу в трёх случаях:

- курсор задержался на ней больше ~65 мс (быстрый пролёт мимо не считается)
- палец коснулся экрана — на мобилках это `touchstart`
- ссылка получила фокус с клавиатуры

Что именно грузится, зависит от маршрута в таблице `routes`:

- `component` — HTML и JS компонента страницы
- `data` — все адреса данных, их качает `$wire`

Если у маршрута нет ни `component`, ни `data`, ссылка просто ссылка.

Теперь самое важное. Данные ложатся в кэш `$wire`, и первый же `$wire.get()` с тем же
адресом заберёт готовый ответ, а не пойдёт в сеть:

```js
// prefetch по ссылке уже скачал этот адрес
$wire.get('Structures/Post-3.json').to(state.post)  // отработает мгновенно
```

Адрес должен совпадать символ в символ — вместе с query. Кэш хранится 30 секунд и работает
один раз: следующий заход на страницу получит свежие данные. Время жизни меняется
в настройках `$wire`:

```js
const wire = createWire({ prefetchTtl: 60000 })
```

Чтобы компонент не грузился сразу при старте приложения, а только когда он нужен
(или когда сработал prefetch), помечайте его ленивым:

```js
.component('Article', 'Components/Article.html', { lazy: true })
```

Подробнее — в разделе про ленивую загрузку.

## Параметры пути
Параметры из шаблона `/post/{id}` читаются через `$route.params`:

```html
<div w-route="post.show">
    <Article w-if="posts[$route.params.id]"
             :article="posts[$route.params.id]"></Article>
</div>
```

Значения всегда строки. Если нужно число — приводите сами: `parseInt($route.params.id)`.

Для `regex:` параметры нумеруются по порядку групп. Именованных групп нет:

```html
<div w-route="regex:/^\/product\/(\d+)\/(.+)$/">
    <p>ID: {{ $route.params[0] }}, название: {{ $route.params[1] }}</p>
</div>
```

Что ещё есть в `$route`:

| Поле | Что внутри |
|------|-----------|
| `$route.params` | параметры пути (`{ id: '42' }`) |
| `$route.query` | параметры после `?` (`{ page: '2' }`) |
| `$route.path` | путь без query (`/post/42`) |
| `$route.name` | имя маршрута из таблицы, либо `null` |

## Query-параметры
Всё, что после `?`, роутер читает отдельно — удобно для фильтров, страниц пагинации и сортировки:
```html
<template id="app">
    <div w-route="/catalog">
        <p>Категория: {{ $route.query.category }}</p>
        <p>Страница: {{ $route.query.page }}</p>
        <button class="next-btn">Следующая страница</button>
    </div>
</template>

<script >
    const { createRouter } = window.jqvm
    const router = createRouter({ mode: 'hash' })

    $('#app')
        .state()
        .plugin(router)
        .method('nextPage', function() {
            const { $router } = this
            return () => {
                const { query } = $router.getLocation()
                const current = parseInt(query.page) || 1
                $router.setParams({ page: current + 1 })
            }
        })
        .on('click', '.next-btn', function(state) {
            return this.fn('nextPage')(state)
        })
        .mount()
</script>
```

URL станет `#/catalog?category=shoes&page=2`.
`$route.query` доступен прямо в шаблоне как часть стейта.

Заметьте: раньше `$route.params` хранил query, а `getLocation()` возвращал `params`.
Теперь `params` — это параметры пути, а query переехал в `$route.query` и `getLocation().query`.

## Регулярные выражения в маршрутах

Для гибкого матчинга — например показать один блок для любой страницы
товара — используйте префикс `regex:`:
```html
<!-- Сработает для /product/1, /product/42, /product/anything -->
<div w-route="regex:/^\/product\/.+/">
    <h1>Страница товара</h1>
</div>
```

Флаги пишутся как обычно: `regex:/^\/product\/.+/i`. Голая регулярка без префикса
больше не понимается — путь вроде `/post/new` слишком легко принять за неё по ошибке.

## Ссылки по имени маршрута
Адрес можно собрать и в JS, и не писать его руками:

```js
const { route } = window.jqvm

route('post.show', { id: 5 })            // '#/post/5'  (в history-режиме '/post/5')
route('post.show', { id: 5, page: 2 })   // '#/post/5?page=2'
```

Лишние параметры уходят в query. Если обязательного параметра не хватает, роутер выбросит ошибку
с названием маршрута — молча сломанная ссылка хуже.

Переход из кода:

```js
$router.go('post.show', { id: 5 })              // push
$router.go('post.show', { id: 5 }, 'replace')   // replace
```

## Реакция на смену маршрута

Хук `$route` срабатывает при каждом изменении URL —
удобно для загрузки данных под новый маршрут:
```js
$('#app')
  .vm({ products: [], loading: false })
  .plugin(router)
  .on('$route', (state, url) => {
      if (url === '/catalog') {
          state.loading = true
          $.get('/api/products').then(data => {
              state.products = data
              state.loading = false
          })
      }
  })
  .mount()
```

## Коротко
- `w-route="/post/{id}"` — показать блок; параметры — в `$route.params`
- `regex:...` — сырая регулярка, параметры по индексу
- `<Link to="name" :params="{...}">` — ссылка с prefetch компонента и данных
- `routes` в `createRouter` — имена маршрутов, `component` и `data` для prefetch
- `route(name, params)` — собрать адрес в JS, `$router.go(...)` — перейти
- `$route.query` и `getLocation().query` — параметры после `?`
